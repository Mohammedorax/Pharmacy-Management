# تهيئة قاعدة بيانات الصيدلية

المرجع الوحيد لمخطط القاعدة الأساسية هو التطبيق نفسه: `Database.EnsureSchemaExists`. لذلك لا توجد نسخة SQL منفصلة يمكن أن تتقادم عن الكود. أضيف سكربت PowerShell يستدعي أمر التهيئة من التطبيق ثم يتحقق من اكتمال الجداول والقيم النظامية.

## ما الذي ينشئه؟

- الجداول الأساسية: الشركات، الموظفون، الأدوية، الفواتير القديمة، المشتريات وبنودها، العملاء، ملف الصيدلية، سجل التدقيق، حركات المخزون، والعملات.
- المحاسبة: دليل الحسابات، مراكز التكلفة، قيود اليومية وبنودها، وسندات المحاسبة، مع المفاتيح المرجعية المتاحة في النموذج الحالي.
- تسلسلات آمنة لأرقام البيع والعميل والشراء وبنود الشراء.
- قيم نظامية غير تشغيلية: العملات الخليجية والعملات الشائعة (SAR عملة النظام الافتراضية)، ضريبة غير مفعلة بنسبة 0، مركز تكلفة رئيسي، ودليل الحسابات الأساسي.
- فهارس للباركود والعملات وحركة المخزون وسجل التدقيق والمشتريات والقيود.

لا يضيف السكربت مستخدمًا أو كلمة مرورًا افتراضيين، ولا أدوية أو فواتير تجريبية؛ هذه بيانات تشغيلية لا ينبغي أن تدخل قاعدة إنتاج من سكربت.

## التشغيل

1. ابنِ `project_fo_3.sln` بوضع `Release`.
2. افتح PowerShell بحساب يملك صلاحية إنشاء قاعدة على SQL Server المطلوب.
3. شغّل من جذر المشروع:

```powershell
.\scripts\Initialize-PharmacyDatabase.ps1 -ServerInstance '.' -DatabaseName 'PharmacyManagementDb'
```

لمثيل SQL Express استخدم مثلًا `-ServerInstance '.\SQLEXPRESS'`. السكربت يستخدم Windows Integrated Security، وهو متوافق مع أسلوب اتصال التطبيق الحالي.

## التحقق بعد التهيئة

يشغّل السكربت التحقق تلقائيًا. يمكن إعادة التحقق دون إنشاء قاعدة جديدة عبر الملف التنفيذي، بعد ضبط `PharmacyConnection` للقاعدة المقصودة:

```powershell
.\project_fo_3.exe --verify-core-schema
```

التحقق يؤكد الجداول والحقول الرئيسية، التسلسلات، العملات والقيم المحاسبية النظامية، والمفاتيح المرجعية الأساسية. فشله يوقف التنفيذ برسالة واضحة بدلاً من تشغيل قاعدة ناقصة.

## طبقة الدفعات والفواتير التجارية

هذه تهيئة **أساسية** فقط. نموذج الدفعات والوصفات والفواتير التجارية لا يثبت عبر هذا السكربت، لأنه لا يجوز إنشاء دفعات تاريخية من الرصيد المجمع. عند تثبيته في بيئة الاختبار يضيف مفاتيح مرجعية من رأس البيع إلى العميل/المريض، ومن البنود والدفعات إلى الدواء، ومن الدفعة إلى بند الشراء؛ لذلك يجب أن تكون بيانات الاختبار متسقة قبل التثبيت. ثبّته فقط على قاعدة اختبار مستعادة ونسخة احتياطية موثقة:

```powershell
.\project_fo_3.exe --install-commercial-schema 'C:\backups\verified-pharmacy.bak'
```

الأمر يتطلب مسؤول Windows محلياً، ويتحقق بـ `RESTORE VERIFYONLY` من النسخة قبل أي DDL، ويرفض أي اسم لا ينتهي بـ `_test` أو `_qa` أو `_sandbox`. بعد نجاح تثبيت الأساس، شغّل مشغّل الترحيلات الموحد لتسجيل/تطبيق الترحيلات الإضافية. يظل `FullCommercial` معطّلًا حتى تثبت مطابقة أرصدة الدفعات وتكتمل اختبارات الضريبة والطباعة وإعادة الطباعة. التفاصيل في [COMMERCIAL_ROLLOUT_AR.md](COMMERCIAL_ROLLOUT_AR.md).
